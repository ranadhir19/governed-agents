# Work twin

A principal-split worker twin with measured discretion.

All data in this application is **synthetic**, produced by a deterministic
seeded generator (`governed_agents.work_twin.generate`). No real mailboxes,
tickets, repositories, or people are involved. Every number in
`results/results.md` comes from an actual run of `demo.py`.

## Problem

Two legitimate objectives pull against each other. Workers want drudgery
removed: commitments and routine drafting live in their heads, and a twin
that holds them is genuinely useful. Organisations want to understand how
decisions are actually made and what can be automated. Built naively on the
same data, the second becomes worker surveillance.

Three further failures are standard in automation analysis:

- **Automation claims are asserted, not measured** -- and when measured, often
  on fields that leak the outcome (a timestamp that exists only because a
  decision was taken) or on labels contaminated by people seeing the AI's
  suggestion first.
- **Analysis drifts from task types to people.** The moment a system answers
  "how does this person decide", it is a surveillance instrument regardless
  of intent.
- **Abstention is not an option.** When nothing recorded explains a decision,
  systems either invent an explanation or silently automate on noise.

## Solution

Split the twin by **principal**, not by subject, and make every capability
earned against a measurement:

1. **Three twins.** Personal (principal: the worker; the employer cannot read
   it), Professional (joint; craft, voice, evidence; the worker can correct
   it), Working (principal: the employer; acts under contract, with a worker
   veto). Data flows **up, never down** -- enforced as a query filter in code,
   not as an instruction. The twin starts able to do nothing.
2. **Cohort analysis over task types, never people.** The one-way boundary is
   structural: no function in `cohort.py` accepts a person/manager/team and
   returns their figures -- the code to do it does not exist. Suppression with
   two rules (minimum cohort 5; maximum single-contributor share 50%);
   suppressed cells return "suppressed" with the reason, never a blank.
3. **Discretion measured, not asserted.** Nine of ten task dimensions are
   arithmetic. The tenth is measured: a task type is rule-like only if a
   non-leaking recorded field separates outcomes by >= 0.45 over >= 8 minority
   cases. A leakage guard rejects fields observed after the decision. Two trap
   task types prove the guard works. Otherwise the result is abstention:
   "nothing recorded explains this decision".
4. **Shadow mode.** The twin commits a sealed prediction; the human decides
   without seeing it -- the seal is enforced in code, so labels are
   uncontaminated at no risk. Temporal holdout: fit on earlier cases, score on
   later ones.
5. **Autonomy ladder L0-L5 per skill.** Five gates must all hold on every step
   up: >= 50 shadow cases, agreement (L3->L4 requires >= 0.90), ECE <= 0.10,
   a leakage-clean basis, and no worker veto. Automation candidacy is a
   screening test only -- it is never reported as a saving.
6. **Build proof.** Deployment is gated on the deployed code recovering the
   planted discretion and catching both traps.

## Architecture

```
src/governed_agents/work_twin/
  planes.py      principal lattice; UpOnlyStore with the up-only query filter
  twins.py       PersonalTwin / ProfessionalTwin / WorkingTwin (+ worker veto)
  cohort.py      task-type cohort analysis with two-rule suppression
  discretion.py  discretion measurement + leakage guard + abstention
  shadow.py      sealed predictions, temporal holdout, agreement, ECE
  ladder.py      L0-L5 autonomy ladder, five gates
  generate.py    deterministic synthetic data (planted discretion + 2 traps)
  proof.py       deployment gate

04-work-twin/
  demo.py        seeded end-to-end run; writes results/results.md + charts.png
  results/       measured results (regenerated by demo.py)
  tests/         26 smoke tests, all passing
```

## Privacy guarantees (enforced in code, not policy)

- A query from the WORKING plane cannot return PERSONAL records
  (`UpOnlyStore.query` filters by the plane lattice).
- Records move up only via `promote()`; downward moves raise; promotion out
  of PERSONAL requires worker authorization.
- `cohort.py` has no person-level function (asserted by AST in the tests).
- Suppressed cells say "suppressed" with the reason -- never a blank that
  reads as zero.
- Shadow predictions are sealed until the human decision is recorded; early
  reveal raises, so labels cannot be contaminated.

## How to run

From the repo root:

```
PYTHONPATH=src python3 04-work-twin/demo.py     # full demo; writes results/
PYTHONPATH=src python3 04-work-twin/tests/test_smoke.py   # 26 tests
PYTHONPATH=src python3 examples/04_work_twin_demo.py      # quickstart
```

## Results (seed 7; from `results/results.md`)

- Discretion: `invoice-triage` recovered as rule-like on `amount`
  (margin 0.554, minority n=48). Trap 1 (`approval_timestamp`) rejected by the
  leakage guard; trap 2 (`risk_score`, margin 0.833) rejected on the
  minority-cases rule (5 < 8). Seven task types abstain.
- Cohort: `1k-5k` suppressed (single-contributor share 80% > 50%);
  `50k+` suppressed (n=3 < 5); two cells reported normally.
- Shadow: 80 cases, agreement 0.963, ECE 0.006; temporal holdout agreement
  0.889 (fit on 81 earlier, score on 36 later).
- Ladder: skill `invoice-routing` earned L0 -> L5, all five gates passing at
  every step. A vetoed working-twin action was refused execution.
- Build proof: deployment gate GO (4/4 checks).
